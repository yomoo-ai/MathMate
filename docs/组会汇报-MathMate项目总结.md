## 一、项目是什么（一句话）

**MathMate 是一个「自然语言/拍照输入数学题 → 大模型生成结构化几何描述 → 网页实时渲染成可交互、可分步讲解的 3D 图形」的教学原型系统。**

它要解决的问题是：高中立体几何教学里，学生看静态插图很难建立空间感；老师画图费时且不可交互。我们的想法是让大模型充当"翻译器"——把题目的自然语言翻译成一种我们自定义的 JSON 格式（GeometryJSON），再由前端程序确定性地把 JSON 画出来。

**核心设计思想：让 LLM 只做"理解"，不做"计算"和"画图"。**

- LLM 负责：读题 → 提取几何元素（点、线、面、体）→ 输出 JSON
- 程序负责：坐标计算（外心、内心、截面交线等）、合法性校验、渲染、交互

这样即使 LLM 算错数，也不会画出错误的图——因为所有数值都是程序按公式现算的，LLM 输出的只是"关系描述 + 表达式"。

## 三、前端与"后端"分别是什么

### 前端（全部自研，纯静态，单页应用）

技术栈：**Vite 5 + TypeScript + Three.js 0.169 + KaTeX**。没有任何前端框架（React/Vue 都没用），全部原生 DOM + 模块化 TS——教学工具交互不复杂，框架反而增加理解成本。

构建产物是纯静态文件（`dist/`），部署到任意静态服务器即可，不需要数据库、不需要常驻进程。

### 后端：**没有自建后端，用双模型协作**

系统唯一的"服务端"是两个云端 LLM API，**分工配合**：

| 模型 | 角色 | 干什么 | 为什么选它 |
|---|---|---|---|
| **DeepSeek**（deepseek-chat） | 主力模型 | 所有数学理解 + GeometryJSON 生成 + 校验失败后的自修复重写 | 数学/代码能力强，价格低 |
| **智谱 GLM-4V-Flash / GLM-4.6V-Flash** | 转录员 | 只做一件事：把拍照的题目图片转成文字 | 永久免费、支持 base64 传图 |

**分工哲学**：视觉模型只当"转录员"，转录出的文字交给 DeepSeek 流水线处理——这样视觉模型输出质量的波动不会影响数学推理的稳定性，两条链路可以独立更换模型（代码里视觉模型做了多档降级链，一个不可用自动换下一个）。

浏览器直接 fetch 调用（本地开发经 vite 代理转发到 `api.deepseek.com` 与 `open.bigmodel.cn`，规避跨域；**线上部署后改由 nginx 反向代理转发**，前端代码零改动），API Key 由使用者在自己浏览器里填、存 localStorage。

这个设计的取舍：

- 优点：零运维、零成本起步、个人使用完全够
- 局限：Key 存在浏览器端，若公开部署，需要加一层轻量代理（服务器上跑 30 行左右的转发脚本，Key 放服务端环境变量）来保护 Key 不泄露。这是后续路线图中的明确项，不阻塞当前开发

## 五、一次完整的数据流（以"求三棱锥外接球"为例）

1. 用户输入题目文字（或拍照：智谱 GLM-4V 先把图片转录成文字，再交给 DeepSeek）
2. LLM 按 prompt3d 配方⑨输出 GeometryJSON：4 个点坐标 + 线段 + `derive: circumcenter` + 球体 `sphere3 { center: 'circumX3(A,B,C,V)', radius: 'circumR3(A,B,C,V)' }` ——注意它**没有算任何数**，只写了关系
3. parser3d 提取并解析 JSON
4. resolve3d 展开 derive，expr.ts 用克拉默法则现场解出球心坐标和半径
5. verifier3d 体检：球心是否 NaN、半径是否正、点是否共面……不过关则把错误发回 LLM 自修复
6. renderer3d 渲染：三棱锥实体（半透明）+ 外接球（更淡的线框球，不参与遮挡计算，避免整图变虚线）+ 坐标轴 + 标签（A/I 自动避让）
7. 读数面板显示 R=1.73、r=0.42、R+r 与棱长关系等（KaTeX 公式）

## 七、预答老师可能的问题（Q&A 备用）

**Q1：为什么不让 LLM 直接算坐标/算截面？**
实测 LLM 解 3×3 线性方程组（求外心）经常算错，且错得"看起来对"。我们把数值计算全部收敛到程序里的表达式求值器，LLM 只输出关系式，错了能被 verifier 定位、能自动重试。

**Q2：LLM 输出格式错了怎么办？**
三重防线：parser 容错修复常见格式瑕疵 → verifier 语义体检 → 失败信息结构化回传 LLM 自动重修。最终还有 58 条回归用例守住程序本身的正确性。

**Q3：和 GeoGebra 等现成工具有何区别？**
GeoGebra 需要用户手动按命令作图；MathMate 的差异点是**自然语言/拍照直达交互图形**，且面向"讲题"——分步显隐、逐步高亮、读数联动是为教学讲解设计的。

**Q4：成本/部署成本？**
主力模型 DeepSeek 按量计费但单次调用极便宜（一道题通常一次对话完成）；视觉转录用智谱永久免费的 GLM-4V-Flash，零成本。**目前已部署到个人阿里云 ECS 上线公网（域名已备案）**：前端纯静态文件由 nginx 托管，LLM 请求经 nginx 反代转发，无数据库、无常驻进程，单台最低配 ECS 即可承载。

**Q5：为什么要两个模型配合？**
拍照识题需要视觉模型，但视觉模型的数学推理不如文本模型稳，且便宜的免费视觉档就够"看字"用。于是让 GLM-4V 只当转录员，数学理解全部收敛到 DeepSeek——两条链路解耦，各自都能独立升级替换。**这一分工经过 A/B 实测验证**：DeepSeek 新推出的识图模型（deepseek-flash）虽可一模型直出，但对几何图标记（平行/垂直/相等记号）的识别不如 GLM-4.6V 细，转录丢一句条件，下游整条约束链就塌——最终回到双模型分工，DeepSeek 识图只作降级备选。
